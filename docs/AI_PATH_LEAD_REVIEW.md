# AI PATH: ручной учёт обращений и стартов

Веб-аналитика и автоматический сбор заявок для этой воронки не настроены. Этот документ и пустой CSV — инструкция для ручного учёта, а не подключённая аналитика или CRM.
Стоимость, длительность встреч и остальные условия пока обсуждаются лично. Учёт не устанавливает новые цены, сроки ответа или обязательства.

## Что считать

- **Полученное обращение:** человек действительно написал по поводу обучения, и сообщение получено по почте или через Solvery. Повторные сообщения по одному запросу не создают нового обращения.
- **Состоявшееся знакомство:** встреча фактически прошла. Запись в календаре и договорённость о времени ещё не означают состоявшуюся встречу.
- **Оплаченный старт:** получение оплаты подтверждено и первое занятие началось. Оплата до первого занятия сама по себе ещё не считается стартом.
- Нажатие `mailto:`, открытие Solvery, скачивание плана и копирование текста не подтверждают обращение. Их нельзя добавлять в число лидов.
- Число посетителей неизвестно. Пока нет соответствующей аналитики, конверсию «посещение → обращение» не рассчитываем.

## Как пользоваться шаблоном

Скопируй [ai-path-leads-template.csv](ai-path-leads-template.csv) в приватный файл вне публичного репозитория. В репозитории оставляй только заголовки: заполненную таблицу не коммитить, не прикладывать к issue или публичным артефактам.
Используй анонимный код обращения. Имена, почту, телефоны, тексты переписки и личные обстоятельства в таблицу не переносить; связь кода с перепиской при необходимости хранить отдельно и приватно.

| Поле | Что записывать |
| --- | --- |
| `lead_code` | Уникальный произвольный код, например `AP-001`; одна строка на один запрос об обучении. |
| `source_channel` | Известный источник и канал получения через `/`; если источник неизвестен, так и написать. Канал получения не доказывает источник привлечения. |
| `program` | ID программы при первом обращении; `unknown`, если она ещё не выбрана. Сохранять исходный интерес для сравнения когорт. |
| `received_date` | Дата первого фактически полученного обращения, `YYYY-MM-DD`, по Москве. |
| `meeting_date` | Дата первого состоявшегося знакомства; до встречи пусто. Запланированное время хранить в календаре. |
| `start_date` | Фактическая дата оплаченного старта; до старта пусто. |
| `payment_received` | Необязательно: фактически полученная сумма с валютой. Пусто означает «сумма не записана», а не ноль; разные валюты не суммировать. |
| `mentor_hours` | Фактически затраченные часы на этот запрос к дате отчёта: знакомство, подготовка и занятия. Пусто — не учтено, `0` — подтверждённый ноль. |
| `status` | `received`, `meeting_planned`, `meeting_held`, `agreed`, `paid_started`, `declined` или `closed`. |
| `refusal_reason` | Краткая обезличенная причина, которую сообщил человек; `unknown`, если причины нет. Не додумывать мотивацию. |

После контакта обновляй существующую строку. Договорённость об условиях отмечай `agreed`; `paid_started` ставь только при подтверждении оплаты и фактического старта, даже если сумму оплаты решил не записывать.
Если человек изменил программу, сохрани исходный `program`; итоговое направление можно отметить в отдельной приватной рабочей записи. Не создавай второй лид из-за смены направления.

## Еженедельный разбор: 10 минут

1. Зафиксируй дату отчёта, новые обращения и изменения по прежним запросам.
2. Отдельно посчитай полученные обращения, состоявшиеся знакомства и оплаченные старты. Не подменяй один этап другим.
3. Для конверсий сформируй когорту по дате первого обращения, например обращения одной недели. Все числители берутся только из этой же когорты и до одной даты отчёта.
4. Покажи число запросов, которые ещё обсуждаются. При сравнении недель используй одинаковое время наблюдения после обращения; свежую незавершённую когорту не сравнивай с давно завершённой как равнозначную.
5. Запиши одну повторяющуюся причину затруднения и одно изменение, которое стоит проверить. Малые числа показывай как `2 из 5`, а не только процентом.

| Показатель | Числитель / знаменатель |
| --- | --- |
| Обращение → знакомство | Уникальные обращения когорты со состоявшимся знакомством / все полученные обращения этой когорты. |
| Обращение → оплаченный старт | Уникальные обращения когорты с оплаченным стартом / все полученные обращения этой когорты. |
| Знакомство → оплаченный старт | Обращения когорты, где знакомство состоялось и затем произошёл оплаченный старт / обращения этой когорты со состоявшимся знакомством. |

При нулевом знаменателе указывай «нет данных», а не `0%`. Старты без знакомства учитываются во втором показателе, но не в третьем.
Не дели старты этой недели на обращения этой недели: это могут быть разные люди. Не заявляй рост конверсии или влияние изменения сайта без сопоставимых наблюдений; ручной разбор помогает найти гипотезу, но сам по себе не устанавливает причину.
Оплаты и часы можно просматривать отдельно для оценки нагрузки. Записанная сумма без затрат, возвратов и полного учёта не является прибылью.
