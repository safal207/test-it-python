# Вайбкодинг: настройка ревью CodeRabbit, Qodo и Codex

> **Инструкция, не автоматическое включение приложений.** В старых проектах Qodo был отключён из-за trial/лимитов. Интеграцию любого провайдера нужно включать осознанно в конкретном репозитории и сверять тариф/доступ. Codex, Qodo и CodeRabbit не получают разрешение на merge.

## 0. Перед тем как подключать бота

- Выбери **один учебный репозиторий**, создай ветку `feat/...` и PR из маленького изменения.
- Сделай проверяемую задачу: для обычного входа и неверного входа должны быть тесты.
- Определи точный commit HEAD и контракты: что менять нельзя, что проверять вручную.
- Убедись, что нет открытых секретов, персональных данных, клиентских доступов или незаявленной чужой лицензии.

## CodeRabbit («кролик»)

1. Открой [официальный CodeRabbit](https://www.coderabbit.ai/) и подключи GitHub App **к выбранному репозиторию**, не ко всем репозиториям без необходимости.
2. Проверь доступы приложения и актуальные лимиты; если оплата/квота не подходит, используй ручной review.
3. Открой PR, посмотри замечания на **последнем head SHA**, сопоставь их с diff и тестами.
4. На каждый подтверждённый дефект: воспроизведение → исправление → регрессия → повторный просмотр.
5. Не считай лимит, «summary ready» или старую реакцию bot `approved` достаточными для merge.

## Qodo Git Review

1. [Официальная настройка Qodo](https://docs.qodo.ai/qodo-documentation/code-review/get-started/configuration-overview/configuration-file). Подключение GitHub App требуется отдельно; наличие файла конфигурации **не активирует сервис**.
2. Если решено подключать Qodo, размести в корне выбранного репозитория `.pr_agent.toml`. Пример минимальной конфигурации (совместимость надо проверить с текущей версией):

   ```toml
   [github_app]
   pr_commands = ["/agentic_describe", "/agentic_review"]

   [review_agent]
   inline_comments_severity_threshold = 3
   ```

3. Проверь на одном маленьком PR, что настройки реально применились, и расход квоты не превышает ожидаемый.
4. У нас Qodo ранее отключали из-за лимитов. Для учебного проекта **по умолчанию не включаем**, предлагаем как опциональный ручной урок.

## Codex Code Review

1. Используй подключённый GitHub и [официальную настройку](https://learn.chatgpt.com/docs/third-party/github).
2. Добавь 2–3 узких правила в `AGENTS.md` (для этого репозитория они приведены в корне).
3. При доступном Codex code review на GitHub попроси `@codex review`. Укажи, например: «Проверь XSS/CSV, CRM demo без PII, мобильную страницу и изменения в CI».
4. Сверь замечание с кодом/логом/тестом и текущим commit SHA.
5. После исправления внеси тест и повторно проверь изменённый HEAD. Автоматически не ставь статус `merge-ready`.

## Типовой процесс одного Pull Request

```bash
git checkout main
git pull --ff-only
git switch -c feat/crm-pipeline-smoke
# Измени одну функцию и тест, затем:
git diff --check
git status --short
git add path/to/changed-file path/to/test-file
git commit -m "test: cover CRM pipeline stage change"
git push -u origin feat/crm-pipeline-smoke
```

Открой PR через GitHub UI, проверь CI. Для AI PATH: основной `npm run check`, браузерный smoke и Lighthouse должны успешно завершиться. Не публикуй телефонные номера, адреса, e-mail клиентов и API-токены в описании PR.

## Что делать с 631 открытыми PR

Не запускать «закрыть все». Используй [актуальный реестр](PR_BACKLOG_2026-10-18.md) и `scripts/audit-pr-backlog.mjs`. Для каждого кандидата:

| Решение | Проверяемое условие |
| --- | --- |
| Merge | exact HEAD, CI, diff, no unresolved blockers, owner approval |
| Fix/rebase | конфликт, блокирующие тесты/ревью, dependency order |
| Superseded close | существует merged replacement с эквивалентным scope, оставлена ссылка |
| Hold | критичные permissions/STOP, приватные память-предложения, внешние upstream |

**Lighthouse** — автоматическая проверка метрик, а не подтверждение получения клиентов или индексации в Google.
