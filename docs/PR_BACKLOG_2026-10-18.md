## Классификация перед закрытием

**A. MERGE CANDIDATE** — небольшая, актуальная, независимая правка; чистый diff; повторяемые тесты на exact HEAD; нет незакрытых review findings; лицензии и секреты проверены; владелец явно разрешил merge.

**B. FIX / REBASE** — конфликт, отсутствующая проверка, race/fail в CI, stale branch, неясное происхождение ассета, недостаточно подтверждённый benchmark или unresolved security finding. Запрещены `force merge`, `auto-merge` и ложная маркировка `merge-ready`.

**C. SUPERSEDED / CLOSE** — только если другая ссылка на PR/merge-коммит доказательно покрывает **всю** функциональность; перед закрытием оставляем комментарий с причиной и ссылкой на замену. Ветки/доказательства не удаляем автоматически.

**D. RETAIN / DECISION REQUIRED** — структурные/опасные изменения, приватные memory proposal, внешние pull requests в upstream, несогласованные публикации. Никаких массовых операций.

## Три варианта ревью

1. **Codex Code Review:** при подключённом репозитории `@codex review`; используем `AGENTS.md` для правил и проверяем текущий head. Codex не является authority для merge.
2. **CodeRabbit («кролик»):** только при действующем доступе/лимитах. Повторный запрос за новый commit после серьёзных изменений, не бессмысленная очередь на десятки PR.
3. **Qodo:** ранее выключен из-за лимитов/trial. Не включать на всех репозиториях без отдельной оценки доступа/стоимости. Репозиторный `.pr_agent.toml` применяется только если выбран этот workflow.

**Минимальная последовательность:** PR → diff/скоуп → независимый человек/бот-ревью на точном HEAD → юнит/интеграция/UI → Lighthouse только для фронтенда → проверка секретов/PII → разбор unresolved findings → ручное merge или документированное закрытие.

Не надо превращать чек-лист в обещание «исправлено 631 PR»: автоматическая инвентаризация ниже только **читает**, никогда не изменяет PR.
